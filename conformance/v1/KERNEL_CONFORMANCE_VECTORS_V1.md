# KERNEL_CONFORMANCE_VECTORS_V1

## Status

SPECIFICATION_DRAFT

This document defines the first conformance-vector surface for `MinimalVerifiableKernel v1.0.0`.

The purpose is to make replay parity testable across independent runtimes and future implementations.

---

# Constitutional Invariant

Given:

1. the same canonicalization manifest,
2. the same ordered event stream,
3. the same replay rules,

any conforming implementation must produce:

1. identical event IDs,
2. identical checkpoint roots,
3. identical final replay root,
4. identical degradation classification.

If any value diverges, the implementation is non-conforming or the input surface is degraded.

---

# Required Vector Shape

Each conformance case MUST be represented as JSON with this structure:

```json
{
  "case_id": "001-basic-genesis",
  "kernel_version": "1.0.0",
  "manifest": {
    "version": "1.0.0",
    "hash": "0x...",
    "rules": {
      "json": "RFC8785",
      "text_encoding": "UTF-8",
      "text_normalization": "NFC",
      "line_endings": "LF",
      "float_policy": "forbidden",
      "timestamp_format": "TAI64",
      "ordering": "index-ascending"
    },
    "pin": {
      "hashFunction": "SHA-256",
      "hashFunctionSpec": "FIPS 180-4"
    }
  },
  "events": [
    {
      "index": 0,
      "payload": {
        "type": "system_init",
        "manifest_hash": "0x...",
        "version": "1.0.0"
      },
      "timestamp": "TAI64N:PLACEHOLDER"
    }
  ],
  "expected": {
    "event_ids": ["0x..."],
    "checkpoint_roots": [
      {
        "index": 0,
        "root": "0x..."
      }
    ],
    "final_root": "0x...",
    "event_count": 1,
    "degraded": false,
    "degradation_notes": []
  }
}
```

Expected values MUST NOT be hand-entered.

Expected values MUST be generated by a locked reference runner and then independently reproduced by at least one other implementation or runtime.

# Initial Vector Set

## 001-basic-genesis

Purpose:

Proves that a single `system_init` genesis event containing the manifest hash produces stable event and replay roots.

Expected verdict:

`PASS`

---

## 002-basic-append-chain

Purpose:

Proves deterministic event chaining across multiple gap-free indexes.

Required events:

1. `system_init`
2. `genesis_attestation`
3. `schema_registration`

Expected verdict:

`PASS`

---

## 003-index-gap-rejection

Purpose:

Proves that a missing event index is rejected instead of silently sorted or repaired.

Input shape:

- event index `0`
- event index `2`
- missing index `1`

Expected verdict:

`FAIL_INDEX_GAP`

---

## 004-duplicate-index-rejection

Purpose:

Proves that duplicate indexes cannot create ambiguous history.

Input shape:

- event index `0`
- event index `1`
- second event index `1`

Expected verdict:

`FAIL_DUPLICATE_INDEX`

---

## 005-nfc-normalization

Purpose:

Proves Unicode normalization convergence.

Requirement:

Two visually equivalent strings with different Unicode byte representations MUST canonicalize to the same event ID only after NFC normalization.

Expected verdict:

`PASS_NORMALIZED`

---

## 006-lf-normalization

Purpose:

Proves line-ending convergence.

Requirement:

Inputs containing CRLF or CR line endings MUST canonicalize to LF-only strings.

Expected verdict:

`PASS_NORMALIZED`

---

## 007-float-forbidden

Purpose:

Proves that unsafe numeric ambiguity is rejected under `float_policy: forbidden`.

Input shape:

- payload contains a JSON number

Expected verdict:

`FAIL_NUMBER_FORBIDDEN`

---

## 008-manifest-hash-mismatch

Purpose:

Proves that a manifest with a claimed hash that does not match its zero-hash-excluded content hash is rejected.

Expected verdict:

`FAIL_MANIFEST_HASH_MISMATCH`

---

## 009-cross-manifest-degradation

Purpose:

Proves historical manifest protection.

Requirement:

Events emitted under an older registered manifest MUST retain their original manifest identity. Replaying against a newer target manifest MUST emit degradation notes rather than silently rewriting historical interpretation.

Expected verdict:

`DEGRADED_CROSS_MANIFEST`

---

# Runner Requirements

A conforming runner MUST:

1. load the vector JSON as bytes,
2. validate the manifest hash,
3. append events in declared order,
4. reject index gaps and duplicates,
5. compute event IDs from canonical payload bytes,
6. compute checkpoint roots,
7. compute the final replay root,
8. compare every computed value with `expected`,
9. emit a machine-readable verdict.

# Acceptance Rule

`KERNEL_CONFORMANCE_VECTORS_V1` is not complete until:

1. the frozen JSON vector files exist,
2. the expected values are generated by the reference implementation,
3. at least two runtimes reproduce the same expected values,
4. the runner emits `PASS` for all positive cases,
5. the runner emits the expected failure class for all negative cases.

Until then:

```text
STATE: CONFORMANCE_SPEC_DRAFT
ANCHOR_STATUS: NOT_READY
```

---

# Non-Negotiable Rule

No expected root may be treated as canonical until it has been produced by executable code and reproduced independently.

Handwritten roots are narrative claims, not proof.
